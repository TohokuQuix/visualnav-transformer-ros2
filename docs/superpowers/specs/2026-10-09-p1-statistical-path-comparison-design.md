# P1 Statistical Path Comparison v1 — Design

## Purpose and scope

Estimate StateGroup-specific differences in the **mean distribution** of the existing 0–2 s discounted reward and common-global-goal progress between each frozen P1 Path and `direct_reference`. Historical 28-run golden, batch v1/v2, Phase A and minimal physics results remain immutable and historically failed under their exact-replay criteria. This protocol has a separate prospective acceptance rule. The first experiment is a variance and feasibility pilot; it cannot be reported as a confirmatory Path ranking or a new training dataset.

The P1 simulator runner calls `policy.act_inference()`. The installed rsl_rl `ActorCritic.act_inference` returns the actor mean; Gaussian `distribution.sample()` occurs in `act()`, which P1 does **not** use. The user chose to preserve `act_inference`. Therefore `policy_noise_seed` is explicitly `not_applicable`; a seed labels observation and simulator randomization, never a claimed matched Gaussian-action stream. Observation noise is additive uniform in the current rough environment. Identical seed labels do not create common random numbers unless an explicit stream-alignment test passes. The primary analysis is unpaired and assignment-aware.

## Frozen inputs and controllable conditions

Use the four original StateGroups, their source fixture, five frozen Path geometry choices (four non-direct and `direct_reference`), the same RL checkpoint, 20 settling control steps, 40 primary control steps at 20 Hz, and steps 40–119 as diagnostic-only. Reward is `sum(0.99**step * reward[step], step=0..39)`; progress is `0.75 m - Euclidean distance from the step-40 root to the common global goal`, expressed in the initial base frame. Record goal-related reward separately. Do not change production ROS follower, frozen Paths, Outcome definitions or policy inference.

For each StateGroup and batch, generate its deterministic terrain mesh **once** and reuse that geometry for seven assigned slots. This includes `boxes`, whose PyTorch CUDA random draws were not controlled by the old NumPy-only seed. Record tile-local vertex/face hash and effective collision/material metadata per slot. If reuse cannot be verified at the live collision representation, do not publish a Path. Generate or populate filler tiles separately; their RNG must not change the seven target meshes. Do not reset global PyTorch RNG inside the per-tile generation loop.

At the pre-Path boundary, restore source fixture root world Z and velocity, local XY/yaw, joint position/velocity and flipper latch. Align ActionManager current/previous action, flipper previous targets and preclip state, accessible actuator targets, latency buffers and observation history across all seven slots by copying one verified source state after settling. Record all fields before and after cloning. Hidden PhysX contact warm starts are recorded as unavailable, not called equal. Accept controlled initialization only if: root local XY spread ≤0.005 m, Z spread ≤0.002 m, yaw spread ≤0.01 rad, root linear/angular velocity spread ≤0.01 in SI units, joint position spread ≤0.005 rad, joint velocity spread ≤0.02 rad/s, and all finite; flipper latch/previous targets, ActionManager actions, latency substeps/buffers, observation history and accessible actuator targets must match exactly. The spatial limits are smaller than one-tenth of the 0.1 m DEM cell, and the velocity/joint limits correspond to small movement over the 0.05 s control interval. These values are prospective design tolerances, not fitted to pilot Outcomes. Failure stops before Path publication.

## Assignment and independent units

Seven slots per StateGroup carry four alternative Paths and three `direct_reference` repetitions. Use a precommitted manifest for **two independent batch seeds** in the initial pilot, with one independently seeded seven-slot scene per StateGroup and batch. Within each batch, assign the multiset to slots by a deterministic random permutation. The second batch must place every non-direct Path at a different slot and must not reproduce the first direct-slot set. Record StateGroup, Path SHA, local slot/env ID, world tile transform, terrain seed/hash, initial-state replicate, batch seed, execution order, checkpoint SHA, observation-noise seed and all relevant source/config SHA. A repeated time step is never an independent unit. Candidate rollouts sharing a batch are dependent; two batches are not enough for strong confidence intervals or confirmatory significance.

Because the policy action is deterministic, the independent seed changes observation and environment randomization. The pilot tests whether repeat variability and tile effects can be estimated; it does not assume seed-level pairing. Direct repeats give within-Path spread within a batch. Rotated assignments give a first location check. A Path effect cannot be separated from location if the manifest does not rotate assignments or if the measured location effect is comparable to the proposed effect.

## Analysis and decision

Calculate per-rollout reward/progress from sealed traces, respecting termination and not using post-reset data as candidate Outcome. Report each metric separately. For every StateGroup and non-direct Path, estimate its mean minus the direct-reference mean. Show per-batch contrasts, raw replicate spread, descriptive 95% cluster-bootstrap intervals that resample **batches**, not steps or paths, and the independent batch count. With two batches, label intervals `pilot/descriptive/underpowered`. No significance claim. Plot direct repeats by tile/env and compare batch-to-batch contrasts. The pilot cannot claim equivalence from an interval spanning zero.

Predefine a practically meaningful difference as ≥0.05 m of 2 s goal progress (half a DEM cell) or ≥0.5 discounted reward units (about 0.0125 per primary step before discount). These are separate margins and do not form a composite. Estimate additional independent batches for half-width no larger than half the corresponding margin using the observed batch-contrast standard deviation and a conservative t critical value; report `unestimable` if fewer than two independent contrasts or variance is nonfinite. For four alternatives per StateGroup and two primary metrics, a later confirmatory analysis must prespecify Holm adjustment and avoid selecting a winner from this pilot. No claim is made across other StateGroups or terrains.

Pilot decision is one of `statistical_comparison_feasible`, `more_repetitions_required`, `experimental_confound_detected`, `protocol_invalid`. A candidate-free initialization check precedes each Path rollout. Stop on mismatched geometry/collision, initialization failure, unresolved Path-slot confounding, uncharacterized noise stream interpreted as paired, Outcome drift, missing provenance, GPU >7680 MiB, host RAM available <10 GiB, active storage >1 GiB, heartbeat stale >90 s or process >600 s. Stop after this limited pilot; no collection expansion or Evaluator training.

## Implementation boundaries

Separate pure manifest and analysis code from the Isaac/ROS runtime. Retain source snapshots, manifest, logs, per-rollout factors and an atomic SHA seal. The runtime owns only its processes and does not start/stop the external Zenoh router. If follower parity or router preflight cannot be established, stop before Path publication and report the missing condition; do not replace the production follower with an unvalidated approximation. No historical artifact is changed.
