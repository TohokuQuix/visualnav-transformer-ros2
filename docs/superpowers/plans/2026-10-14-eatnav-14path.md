# EAT-Nav 14-Path execution plan

## Frozen intent

- Start from commit `00a8b14`; leave MI-A/MI-B evidence and checkpoints read-only.
- Preserve the existing robot-relative 0.75 m, eight-point bank geometry and the RL Actor, C++ follower, physics, DEM, noise, and numerical Gate P.
- Keep the latest DEMO selector's **global-goal** progress objective, as confirmed by the user on 2026-10-14. The attachment's local-goal score is superseded.
- Use independent persistent evidence roots, manifests, source hashes, SHA ledgers and seals for each stage.

## Stage A: large-angle feasibility

1. Freeze a new 32-process schedule: `random_rough` level 2, existing terrain seed `2026101602`, both initial flipper postures; per posture two pre-Path repeats followed by all fourteen candidate Paths in bank order. Four env tiles per process.
2. Verify Direct and ±30° coordinates and byte SHA against the sealed MI-A v3.1 records; audit ±60°/±90° origin, finite geometry, arc length, first tangent, curvature, interval lengths, endpoint and symmetry.
3. Run new-version host/simulator with the unchanged 20-step settling, 40-step labels and Gate P. Stop on the first protocol or resource failure; do not exclude low motion, stall or small forward speed.
4. **Pass** only if all 32 process seals and Gate P checks pass, all 112 candidate traces have 40 finite steps and finite XY/yaw labels, Path publication and C++ follower commands are present, and no unexpected reset/termination invalidates a label. **Fail** on verified protocol/geometry/label violation. **Inconclusive** on missing evidence or infrastructure failure that prevents a scientific decision. No minimum displacement is imposed.
5. Report motion, velocity, yaw, follower command, contact and termination by posture, direction and angle. Distinguish scientific low-motion results from protocol failure.

## Stage B: paired collection

1. Freeze three unique 32-bit terrain seeds per terrain×level cell, including at most one old MI-A seed per cell. Assign all 36 seeds to train/validation/test before collection, one seed per cell per split.
2. Run a small validation and resource smoke. If it passes, collect two posture conditions × four tiles × fourteen Paths per seed with the Stage A protocol, fresh-process reference and Gate P. Preserve all attempts, including failures.
3. Audit the target of 36 independent seeds, 288 paired groups and 4,032 candidate trials before model training.

## Stage C: 14-candidate predictor

1. Freeze metric definitions, split, acceptance thresholds and training settings before viewing test metrics.
2. Build a K=14 grouped dataset; use train-only normalization and validation checkpoint selection. Audit any reuse of six-Path legacy data for duplicate seeds and split leakage.
3. Train Full and No DEM/No Body/No Path models; compare a Direction mean baseline and the six-Path checkpoint on its supported candidate subset. Evaluate seed-level uncertainty, angles, direction, posture interaction and terrain strata.
4. Adopt the model for DEMO only if the frozen acceptance gate passes; otherwise report the failure without changing the model or gate after test inspection.

## Stage D: DEMO integration

1. Use the robot-forward 14-Path bank and global-goal progress of predicted two-second body-frame displacement. Preserve the existing Front-folded reset and old-checkpoint selection option.
2. Verify checkpoint/geometry compatibility, fourteen visualized candidates, TF/frame/timestamp, follower command and end-to-end GUI motion. Stop on incompatibility or failed Stage C gate.
