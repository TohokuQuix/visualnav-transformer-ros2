# MI-B Pilot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Test whether sealed MI-A candidate trials support held-out prediction of 2-second body-frame motion and paired Path effects.

**Architecture:** Verify all MI-A seals and labels before building a separate grouped dataset. Train one small CNN/MLP architecture with fixed modality masks for Full and three ablations. Evaluate the sealed test split once, with seed-clustered descriptive reporting.

**Tech Stack:** Python, NumPy, PyTorch CPU, pytest.

**Spec:** User-provided MI-B Pilot request and `docs/eat-nav/motion-predictor-vnext/mi_b_pilot_contract.json`.

## Global Constraints

- MI-A evidence is read-only; all new data and checkpoints live in a distinct experiment root.
- Same terrain seed, posture and env tiles stay in one split; each terrain appears in train, validation and test.
- Train-only normalization and model selection by validation; test never selects a checkpoint.
- No Goal input, simulation, RL Actor/follower/physics changes, Phase C or real robot work.

## Review Focus

- Candidate labels must be recomputed from each sealed 40-step trace and match stored labels.
- State/DEM must be pre-Path and Path-independent within a grouped example.
- No-Path outputs must coincide among same-direction candidates by construction.
- Masked candidates must never enter training or metrics.
- Test rows and model choices must remain fixed when reporting ablation differences.
