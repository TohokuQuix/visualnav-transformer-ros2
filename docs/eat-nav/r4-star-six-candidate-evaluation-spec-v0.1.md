# R4*: 後退±30度のみを追加する6候補比較 v0.1

2026-10-26 JST。利用者の「R4を完遂した後、後退候補を3本へ増やす以外は変更しない」という実行指示を固定する。

R4の前進直進・前進−30度・前進＋30度・後退直進の順序を保持し、末尾へ後退−30度、後退＋30度を追加する。前後各3本、合計6本。各候補は既存bankの0.75m・8点。角度は既存bankの進行方向の定義を引き継ぐ。

採用方式は既存checkpointをそのまま6候補へ適用する方法。ネットワークは候補別の共有encoderであり候補数を可変に扱える。再学習・追加収集・正規化再fit・閾値調整をすると候補追加以外の差が生じるため今回は行わない。既存4候補の同点順を保つため2本は末尾へ追加する。

直線stallのみ有効、他のriskと実測姿勢STOP/復帰は無効。採点式・直線risk重み1・除外p>=0.95かつ10秒progress<=0.05m・全候補除外STOP・最短2秒停止・2回再開確認・候補4秒保持・0.15切替margin・前後進2回確認はR4と同じ。前後進の区別は候補index3固定判定から各候補のdirection判定へ拡張し、後退3本すべてへ同じ規則を適用する。

全7field、同じ12モデルとSHA、同じ36割当の学習/走行seed・実行順、Actor/env YAML、terrain/level/geometry、初期化・settling・最大60秒・20Hz・2秒再評価・経路継足し・waypoint列・正常到達基準・85度転倒終了・boundary censorを維持する。後退曲線の継足しも既存bankと同じbody heading規則を使う。学習seed反復と独立走行seedは区別する。reserved testは未開封。

現在実行中のR4のsource/manifest/outputを変更しない。別名のsourceと出力directoryで準備し、R4の全36予定処理と終了後再現監査がsealedになってからR4*のGUI走行を開始する。終了を待つ処理は実行processとして記録する。失敗seedの置換や成功までのretryはしない。

同一初期状態のR4/R4*を対応比較する。anchor-stateの全数値配列、DEM・Actor/body入力は一致を要求する。candidateに関する3配列(paths/directions/candidate_mask)だけはR4*の先頭4本をR4と照合し、新規2本はbankと照合する。shapeが違うだけで入力不一致扱いにせず、共有入力の差を無視もしない。比較不成立はN/A。

各保存入力で6候補の全head生予測・実際に使用したlinear予測・全step guard状態・STOP時3軸0を再現監査する。変更前4候補の予測が同一入力上で一致することも検証する。候補別選択回数/走行秒、とくに新規後退曲線の利用を記録する。進捗・転倒観測・STOP秒・観測時間・正常waypoint・動作中linear stallを同じ有効case集合で比較し、差だけで改善を断定しない。起動時の失敗も全件保存する。

追加した後退曲線は現行の4候補学習datasetで直接学習していない形状である。同じweightsでの候補拡張実験として解釈し、未学習形状の予測精度を保証しない。改善しない場合は候補の利用有無・予測・追従outcomeを確認する。

GUIを表示し、実起動時のhost/Dockerコマンドを表示・保存する。全件完了後に再現監査とR4対R4*の比較報告を別rootへ保存する。
