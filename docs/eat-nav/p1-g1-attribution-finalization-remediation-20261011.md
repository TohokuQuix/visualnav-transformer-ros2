## Corrected protocol, prepared but not run

`eat_nav_p1_g1_gpu_host.py` now launches the already established standard-library-only owner wrapper. The wrapper records its container PID, namespace PID chain, start tick, command token, source/config SHA, and output root, then waits **before Isaac import or physics**. The host saves every failed mapping diagnosis and candidate `/proc` row, requires an exact cgroup, namespace, token, PID and start-tick match, samples an NVML/process-table bracket while the wrapper is paused, and only then writes authorization. After `execv`, the same PID/start tick identifies the simulator. NVML rows use host PIDs and are checked against the host `/proc` process tree; unknown, vanished, or mismatched PIDs fail closed. At least one live owned GPU sample is required for G1 pass. The GPU attribution gap limit remains **256 MiB** and all frozen GPU, RAM, disk, heartbeat, and wall-time limits remain unchanged.

Finalization order is: stop or await the exact owned simulator; wait for the Docker client and any recorded owned processes; close and fsync the resource, PID-poll, and combined log writers; verify trace/completion and write cleanup/status evidence; then generate the SHA ledger and host seal. A live exact owner, recorded child, or unresolved run-token claimant prevents sealing. A seal verifier checks every recorded file and detects changed or added files after sealing. On a failed gate, flushed raw trace and monitoring evidence remain in the new output root; a live writer leaves the root explicitly unsealed rather than producing a misleading seal.
