# P1 G3 protocol revision: pre-Path DEM and state alignment audit

## Scope and conclusion

This is a **static design audit**. No Isaac simulation, candidate trial, training, or collection was run. The G1/G2/G3 and candidate-free DEM diagnostic originals were not modified. The existing one-run DEM diagnosis showed that a roughly 0.00095 rad pre-clone yaw difference explains the direct duplicates' robot-relative DEM gate failure: replacing only env 1 yaw in an offline recomputation removed all frozen-threshold violations. The mechanism that caused the physics divergence during settling remains unknown.

No product code was changed in this audit, so no new synthetic test was needed. Read-only seal validation reconfirmed the G1/G2/G3 and DEM diagnostic evidence; `git diff --check` passed for this report.

**Recommendation:** retain the 20-step representative settling trace, clone the full visible branch state at its end, and assign the representative env's four **already encoded robot-relative DEM frames** as a common, immutable *experimental input* to all four branches. Keep every env's actually measured pre-clone ray history in a separate diagnostic record. Apply the existing numeric thresholds to the common input as a distinct `shared_DEM_input_equality` gate, while reporting measured sensor equality separately; never relabel the measured histories as equal. This is a proposed G3 protocol change, not an approved or implemented trial. It isolates Path as the planned intervention while avoiding another physics step before Path exposure. It does not make unreplicated PhysX or contact state identical, so direct duplicate outcome parity remains mandatory.

| Can the sensor's four-frame history be reset or rebuilt? | RayCaster stores current `ray_hits_w`, ray starts/directions, pose, drift, and update timestamps, with no four-frame history buffer. `RayCaster.reset(env_ids)` calls `SensorBase.reset`, zeroes sensor clocks, marks buffers outdated, and resamples drift. The EAT grid scanner uses world-aligned rays; its update period is set from `dem_history_interval_sec`. G3 creates its four-frame history itself at settling steps 4, 9, 14, 19. [RayCaster:120–137,234–235,294–308; SensorBase:169–182; EAT cfg:211–238; G3 simulator:361–378] | Recasting once after clone yields a **current** frame, not four historical frames. Repeating a current frame four times would fabricate temporal history. Calling `reset` also alters timestamps and invokes drift sampling (configured defaults are zero but RNG effects must be checked), so it is unsuitable as an undocumented history-rebuild mechanism. A task-level immutable history object is safer. |

It must not be treated as side-effect-free merely because `update_history=False`. ## Options for G3

| Option | Physical state after alignment | Observation semantics | Complexity and causal interpretation | Assessment |
|---|---|---|---|---|
| **1. Recast after clone without physics** | No extra integration, so no new physics divergence from the recast itself. | One current measured frame can be refreshed if sensor invalidation/view synchronization works. Four *historical* frames cannot be recovered from the single cloned pose. Manually changing private sensor flags or resetting its clock has side effects. | Medium/high implementation risk; repeating one frame or rewriting past sensor timestamps would change the temporal input and weaken the meaning of the comparison. | Useful as a **current-frame diagnostic**, not the primary history reconstruction. Require runtime proof before relying on private API. |
| **2. Copy env 0's robot-relative four-frame history** | No extra physics step; branch root/joint and copied visible state remain at the clone anchor. | All branches receive identical, genuine env-0 historical input. Native raycaster buffers remain branch-specific; measured native history must be retained and reported separately. | Low/medium implementation cost. Strongest controlled comparison of candidate Path under a common observed-history covariate, provided input provenance is explicit. Does not solve solver/contact state divergence. | **Recommended** for the revised matched-branch G3 pilot, subject to pre-Path state/Actor/Critic/contact checks and post-Path duplicate gate. |
| **3. Settle after clone and recapture** | Physics resumes and branches may separate again; the existing 20-step settling already produced measurable pose/yaw differences. | Can collect genuine per-env temporal frames, but they may disagree again. A second clone at the end would again leave historical frames from before that clone. | Highest runtime and causal ambiguity; adds a new pre-Path trajectory/elapsed time and may change warm starts and outcomes. | Do not choose as the primary fix. Use only if a separate physics-divergence experiment is approved. |

## Proposed independent gates and required code changes

1. **Physical state gate:** after representative settling and clone, check root pose in tile-local coordinates, joint state, command, action/latency buffers, observation-history rings, episode counters, and relevant controller readiness against the existing pre-Path limits. Preserve `require_prepath_gate` and its thresholds. Record exactly which state was copied and which remains unreplicated. Do not call another physics step while preparing DEM input.
2. **DEM input gate:** keep the frozen `direct_dem_gate` implementation and its height RMS `1e-5 m`, max absolute `1e-4 m`, and mask IoU `1.0` limits. Apply it to the immutable common **encoded** four-frame history that each branch will actually receive. Check shape, axes, resolution, frame identity, order, source SHA, and byte-level copy integrity independently. Save a distinct `measured_native_DEM_history` comparison with the same numeric metrics, even when it fails; its failure must not be silently recast as a sensor pass. This change in gate *meaning* requires a new G3 protocol/version and explicit approval, even though the thresholds stay frozen.
3. **Actor/Critic/contact gate:** generate one observation per control step. Compare pre-noise, post-noise/pre-delay, and actual post-delay Actor input, plus Actor action under paired noise. Record Critic terms separately, especially the Critic scanner and contact binary. Sample contact force/history and current sensor update stamps before Path exposure; any unequal input that can affect Actor command or reward must be reported and judged before candidate interpretation. Do not reset contact sensors just to equalize records; their buffers reflect PhysX contact history.
4. **Follower and post-Path gate:** retain the exact-stamp follower/bridge readiness and the existing direct duplicate arrival, tracking, progress, command/action/trajectory, recovery, and body-load reproducibility checks. If duplicate variation is comparable to a candidate effect, stop rather than attribute it to Path. Preserve one Path publication per trial, paired noise, resource caps, and no automatic retry after exposure.
5. **Timestamp contract:** the captured frame is taken *after* settling step `s`, so logical acquisition time is `(s+1)×50 ms`, not `s×50 ms`. Store that corrected logical stamp and the raycaster's actual `_timestamp_last_update` separately (including precision and update-age diagnostics). Do not overwrite original timestamps; adopt the correction only in a new versioned manifest/source and verify monotonic four-frame spacing and per-env equality.

Code to change after approval: add a versioned history provenance structure and a copy/validation helper alongside `p1_dem_capture.py`; split physical, shared-input, and measured-native DEM diagnostics in a new G3 simulator/manifest; update host seal validation to require each artifact and provenance SHA. Keep the original G3 and one-run diagnostic artifacts untouched. No production follower, RL checkpoint, terrain, Path geometry, or numeric thresholds need changing.

## Proposed runtime validation before candidate exposure

1. Run synthetic tests for immutable four-frame copy, tile-local/robot-relative metadata, source SHA and frame ordering, actual versus logical timestamp fields, and both independent gate outcomes. Show that measured-native DEM may fail while shared-input equality passes, without changing the old gate function.
2. With separately approved new persistent root/source SHA, run one candidate-free 4-env 20-step check. Verify no Path publication, exact post-clone physical-state gate, all shared DEM input SHAs, Critic/contact/Actor term differences, no extra physics step, actual sensor timestamps, GPU attribution, cleanup, host/container SHA, and seal. An optional **separate** current-frame raycaster refresh diagnostic may test private invalidation; it is not needed for the shared-history proposal.
3. Only if that check passes, seek approval for a direct-duplicate Path reproducibility control before curved candidate outcomes are interpreted. Preserve the original post-Path duplicate thresholds; investigate unreplicated PhysX/contact/follower state if it fails. A full G3 candidate pilot would require another approval.

## Remaining risks and decisions for review

- Sharing encoded history creates a controlled counterfactual observation, **not** four per-env measured DEM histories. Its validity is limited to a matched Path-comparison pilot; it does not establish online sensor parity or navigation-policy performance.
- The cause and onset of the settling-time yaw divergence are unknown. PhysX contact warm starts, contact-sensor history, and global RNG are not fully cloned. No static argument guarantees duplicate rollout equality after Path publication.
- A no-physics raycaster refresh uses internal APIs if a fresh cache is required. The exact pose-view coherence, sensor timestamp handling, and possible RNG effect require runtime validation. It cannot by itself reconstruct historical frames.
- Review decision needed: approve **option 2 with separate shared-input and measured-native histories**, or request a different experimental question. No protocol implementation or runtime experiment was performed in this audit.
