# 14-Path paired collection protocol v1

Stage B starts only after Stage A `eatnav_motion_14_stage_a_v1` passes all
32 process gates. Thirty-six unique 32-bit terrain seeds are generated by
`motion_14_collection.seed_groups()`: three distinct seeds per four
terrain types × levels 1, 2 and 3. The split is fixed by each derivation
token's `train`, `validation` or `test` suffix: one independent seed per
terrain×level cell per split. All seeds are disjoint from the twelve MI-A
v3.1 seeds. No outcome or model metric influences allocation.

For every seed, both Front-folded and Rear-folded conditions run in separate
fresh processes. Each condition has two pre-Path repeats, then Forward and
Reverse `(0, -30, +30, -60, +60, -90, +90)` in frozen bank order. Four env
tiles yield 288 paired StateGroup×posture×tile groups and 4,032 Path trials.
Every candidate executes 40 control steps at 20 Hz after 20 settling steps.
The frozen Actor, C++ follower, physics, DEM, noise, material and numeric Gate
P remain unchanged from Stage A. Angles specify the reference Path tangent
turn, not a measured body yaw.

Native ray hit and start world coordinates, ray-valid mask, robot root state,
tile origin and four logical DEM stamps are preserved in a separate
`raw-dem.npz`. The transformed robot-relative DEM history remains in
`prepath.npz`; raw fields do not silently extend the frozen Gate P comparison.
All attempt files are written to new persistent subroots and sealed. Source,
checkpoint, config, assignment and protocol SHA are fixed before the smoke.

The first seed's 32 processes are a smoke gate and part of the formal dataset
if protocol-valid. They are not rerun. Smoke Pass requires all 32 host/inner
seals, Gate P comparisons, native ray source SHA, 40 finite rows per candidate
tile, available body-frame XY/yaw labels, and resource checks. If any fail,
stop without starting remaining seeds. The remaining 1,120 processes run in
fixed manifest order, sequentially, with the same per-process gate.
Resource hard caps remain 6,656 MiB GPU device-total, 2 GiB minimum host
available RAM, 800 MB per batch storage and 600 seconds per process.

Low progress, stall, or near-zero forward speed is an observed outcome, not a
reason to drop a candidate. Protocol failure, invalid label, reset before
40 steps, missing files, resource excess and Gate P failure stop the
schedule; completed sealed attempts remain unchanged. A success-only subset
must never be promoted to the 4,032-trial paired dataset.
