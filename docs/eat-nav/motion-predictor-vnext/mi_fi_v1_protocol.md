# MI-FI v1 flipper initialization diagnostic

This is a separate experimental series from sealed MI-A v1/v2, B-R0 and B-R1. The only intervention is the reset event's existing three-pose selection. `front_folded` selects pose index 1 and `rear_folded` pose index 2. Both retain fold mode 0, the frozen Actor checkpoint, follower, Path bank, terrain, physics, noise, latency, 20-step settling, four env tiles and 40-step (2 s) outcome horizon. No flipper pose is imposed after reset.

Execution order is the 16 rows in `mi_fi_v1_frozen_manifest.json`: for each condition, two candidate-free fresh-process pre-Path captures followed by Forward/Reverse Direct and ±30° candidates. Each condition has its own sealed reference. Gate P compares identity and numeric state only within a condition at the unchanged `1e-6` absolute tolerance. Gate M records mirror asymmetry and never stops the run. Differences between the two conditions at Path activation are part of the initialization intervention. Nonfinite state, joint limit violation, unexpected reset or termination, resource cap, missing SHA or failed seal stop subsequent rows.

The reset event uses joint order rear-right, rear-left, front-right, front-left and pose values defined by the resolved `OnixRoughEnvCfg`: extended 0 rad and folded π rad. The runtime records the configured and measured reset angles and soft joint limits, then the measured post-settling angles. The ROS-free PureFollower receives the measured post-settling Path origin. Its four instances remain independent. Each candidate Path is activated once per env.

The primary labels are 2 s body-frame ΔX, ΔY and wrapped Δyaw relative to the measured Path activation pose. Within each condition, Arc minus same-direction Direct estimates Path effects. Between-condition differences of those effects estimate initialization × Path interaction. Forward/Reverse Direct differences and per-step flipper position/velocity/torque, root state, contacts, Actor input/action and command are reported separately. This single terrain seed and its four tiles cannot establish generalization or train Motion Predictor. Contact force alone cannot identify a specific flipper-terrain collision.

Evidence uses a fresh persistent host root, per-attempt manifest, simulator trace, resource series, host/container SHA ledgers and inner/outer seals. The runner stops at the first failed process; no automatic retry or expansion is permitted. Existing sealed evidence is read-only.
