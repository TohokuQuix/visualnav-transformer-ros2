## Decision boundary and evidence discipline

Use an isolated source checkout, ROS domain, build prefix and persistent evidence root. Before runtime, freeze the source/manifest/input/checkpoint SHA ledger, paired fixtures, numeric tolerances, synchronization limits, expected topic/Path contract and first-failure stop rule. Preserve raw messages and tensors alongside decoded values and stage-specific timestamps. Select no model on test or held-out outputs. A missing seal, unsupported Stage C decision, unexplained tensor mismatch, stale input, unexpected reset or unverified stop ends the current gate; do not advance or reinterpret it as a Path-quality result.

If Stage C `demo_adoption` is not `pass`, keep `learned14_adopted` disabled. The CPU mock and pinned legacy modes may still be used for communication diagnostics, but they do not establish 14-candidate learned selection or permit an Isaac performance claim. The adopted checkpoint, normalization, candidate order, geometry and model source must match the sealed Stage C result and the Phase 2 worker's strict loader checks.

## Sequential gates for a separately approved Phase 3

| Gate | Work and required evidence | Pass condition and stop |
|---|---|---|
| P3-0: provenance/readiness | Read-only confirm Stage B/C completion, Stage C adoption decision, selected checkpoint and normalization SHA, source/bank/contract identity, independent evidence destination and private ROS environment. Capture the exact Stage B DEM/Actor preprocessing and Stage C direct-inference function. | All identities and source contracts resolve. Unknown or non-Pass adoption blocks learned14 testing; no fallback is labeled as adopted. |
| P3-1: model numerical parity | On the **same sealed input tensors**, run direct Stage C checkpoint inference and ROS2 Model Worker inference using the same CPU backend, dtype, normalization and candidate mask/order. Compare raw `[4,2,20,20]` DEM, `[22]` Actor, `[14,8,2]` Path, `[14,1]` direction, `[14]` mask; normalized tensors; all `[14,2]` predictions; global-goal scores; and selected candidate ID. Include negative height and invalid-mask fixtures plus tie and masked-candidate cases. | Freeze per-stage exact/absolute tolerances before running. Any unexplained mismatch, source/normalization discrepancy or different selected ID stops. A matching choice alone is insufficient. |
| P3-2: ROS input/time parity | Send measured or sealed DEM/Actor/TF through the separated ROS nodes and compare the worker-bound tensors against the direct learning-input builder. Record four source stamps, actual update stamps, publish/receive/inference stamps, frame IDs, robot pose, episode ID, TF stamp and age. Test normal 250 ms cadence, jitter, missing/reordered frames, stale Actor, TF loss and recovery. | Numerical parity and order hold for valid input. A duplicate frame does not refresh age; no new Path on incomplete/stale data; the 300/500 ms lease policy and exact-stamp TF contract hold. No unstamped/latest-TF substitution. |
| P3-3: 14 selection and Path transfer | With the adopted checkpoint only after P3-1/2, compare all 14 candidate predictions and global-goal distance-reduction scores to a direct calculation. Check fixed order, direction, mask/tie rule, chosen Path SHA, eight body-frame points, map transform, stamp, generation and one publication. Route first to the independent mock interface; later simulator transfer needs its own authorization. | Chosen ID and Path bytes/geometry agree with the frozen bank and selected score. No direction, frame, generation or publication mismatch. Local Path arrival is not global-goal success. |
| P3-4: authorized Isaac integration and stopping | Only after explicit approval, test one controlled Isaac Lab state with the separated nodes and a simulation-only gateway. Compare source and worker tensors, selected Path, follower receipt, command, Actor observation/action and physics timing against the frozen contract. Exercise Cancel, timeout, DEM outage, TF/worker loss and fall reset; check held-Path invalidation, zero simulated command, and fresh four-frame rearming. | Exact causal ordering and each stop mechanism are observed in raw evidence with bounded latency. Any nonzero command after invalidation, stale Path reuse, unverified reset or resource/protocol failure stops. Do not infer real follower behavior from the mock/simulator. |

The first runtime review should authorize only the smallest single-state simulator gate after P3-0 through P3-3 are satisfactory; expansion needs a further review. Any comparison with the existing DEMO or Stage B rollout is a separate protocol with matched inputs and provenance. Do not mix Phase 2 mock, legacy-six, adopted-fourteen, collection or GUI outcomes in one performance dataset.
