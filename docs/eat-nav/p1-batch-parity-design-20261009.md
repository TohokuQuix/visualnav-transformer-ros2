# P1 28-run golden parity: design and stop gates

The SHA-sealed 28 physical P1 runs in `/home/kojima/eatnav-backups/2026-10-09-p1-radial-28-analysis/` are the reference. The failed old tenth process is excluded. All batch comparisons use the stored P1 command, Actor, root, reward and Outcome traces; no labels are regenerated from candidate results.

1. **Golden contract.** Verify the backup seal, integrated manifest, all 28 run seals, raw output ledgers and candidate trace SHA before work. Pin the production follower source, binary and parameter SHA. Do not alter the production ROS node or its installation.
2. **Pure follower.** Build a ROS-independent calculation unit with one state object per target env. Input is Path geometry, robot pose, logical time and the follower's explicit persistent state; output is command and updated state. Port the P1-exercised production behavior from the SHA-pinned C++ source. Explicitly reject any unimplemented recovery state rather than silently approximating it. Compare all 3,360 P1 command steps offline before simulation.
3. **Mixed scene.** One existing 112-env Isaac scene has 28 target slots: seven candidate/repeat slots per StateGroup. Generate the exact terrain type and per-tile seed for each target slot. Original P1 scene indices overlap across batch seeds, so this is a translated tile layout; compare root positions after applying a frozen original-to-batch tile translation, and compare DEM and Actor signals in their robot-local frames. The interpretation of root equivalence is pending the user's answer. Before publishing any Path, verify terrain/collision identity, 200-step settling, root/joint, four DEM frames and Actor pre-noise/post-noise/post-delay observations for all 28 slots. Stop before Path on any mismatch.
4. **Batch rollout.** Publish each target Path once after the pre-Path gate. Run the pure follower, Actor and physics for 120 control steps; keep target env state, observation noise/latency, command, termination and reset records separate. Forbid output-after-reset from entering that env's Outcome. Compare P→C→A→R→Y at every step with P1. The 40-step discounted locomotion return and common-global-goal progress are distinct primary labels. 120-step progress/termination are auxiliary. Safety remains disabled.
5. **Protocol.** Freeze numeric parity tolerances and resource caps before any batch result. Use atomic per-env markers, SHA ledgers, lossless compression with roundtrip SHA, exact owned cleanup and resume that skips only verified sealed envs. No automatic retry after Path publication. A duplicate failure, timeout, resource violation or unexplained parity deviation stops the batch; do not loosen thresholds.
6. **Decision.** If all 28 target envs pass command/action/trajectory/reward/Outcome and direct-clone gates, prepare an 8–12 independent-StateGroup stratified pilot and runtime/storage estimate, then stop. No additional rollout, full collection, Evaluator training, production follower change or online selector is in scope.

The original P1 terrain generator uses one batch seed per entire 16×7 scene, while the golden anchors use two seeds and reuse env index 48. Exact global XY for both source terrains cannot coexist in one scene; any batch mapping must be explicitly defined and validated before Path publication.
