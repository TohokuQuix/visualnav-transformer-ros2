## 3. Candidate geometry and horizon

The P1 frozen local-motion bank has **five** eight-point circular arcs at bearings −20°, −10°, 0°, +10°, +20° relative to the anchor. The implicit start is (0,0); every endpoint is exactly 0.75 m from it. From `docs/eat-nav/local-primitive-p1-r5-20261008-attempt2/frozen-primitive-paths-r3.json` at commit `67a1acf`, polyline arc lengths are respectively **0.7652, 0.7538, 0.7500, 0.7538, 0.7652 m**. The ±20° endpoints are (0.70477, ±0.25652) m; ±10° are (0.73861, ±0.13024) m; direct is (0.75,0). Curvature peaks at about 0.912 m⁻¹, below the prior 1.236 m⁻¹ **offline follower screen**, which is not a physical limit. The `docs/eat-nav/local-motion-primitives-20261008/local-motion-primitive-contract.json` contract in that commit excludes reverse and self-intersection. The five Paths have **different local endpoints** except the direct Path; the common navigation goal remains (0.75,0).

At nominal 0.3 m/s, 0.75 m requires roughly 2.5 s before turning/terrain delays. Because the follower stops at the local endpoint, a 20–30 s single-Path rollout can mostly measure a stopped robot, while an unreached/stuck Path may activate recovery after ~20 s. These are different outcome classes; additional duration alone cannot make a local Path into a navigation policy. In particular, own-endpoint arrival must not be mislabeled as common-goal success. The ±20° local endpoints remain about 0.26 m from the common goal even if tracked perfectly.

## 4. Proposed label and input contract

Retain a multi-field record per `(anchor, Path, independent noise block)` with mutually distinguishable statuses:

| Field family | Definition |
|---|---|
| Protocol | Path/source/config/checkpoint SHA, anchor/terrain/seed, noise-stream SHA, time and TF/command acceptance, termination and missingness reason. Invalid measurement is never a poor Path label. |
| Local execution — primary | `local_goal_reached`, first time and first mechanism (`distance_tolerance` or `goal_line`), arrival pose, remaining Path arc length, time-indexed cross-track error and terminal heading. If unreached at the cap: `right_censored`, last/minimum remaining distance and exposure duration; do not impute failure time. Record 2 s post-arrival stop-hold integrity separately. |
| Navigation progress | Initial/final/minimum distance to the **fixed common goal** and along-goal/lateral displacement at predeclared 2 s, 6 s, and end-of-exposure landmarks. A 6 s value is `not_exposed` if the 2 s post-arrival stop check ended earlier; never extrapolate it. Keep this independent of local-endpoint success. |
| Recovery | First trigger time, count, type (angular, linear command-vs-motion, or Path-progress stall), boost/backtrack duration, and resolution/censoring. A timer that has not yet matured is `not_observable_yet`, not `no_recovery`. |
| Body load and locomotion | Discounted reward by fixed window, body forward/lateral velocity, command tracking, roll/pitch, flipper motion/torque, per-body contact and physical termination. Contact force alone does not identify traction/slip. Keep arrival, tracking error, recovery and body load as separate fields; no scalar Quality target is frozen here. |

Evaluator inputs at decision time may include the four-frame DEM history/mask, robot-relative candidate Path geometry, relative common goal, measured current body/track proxy state and prior observations that actually exist before publication. They may **not** include future follower commands, realized trajectory, recovery events, Critic values from a privileged future state, success labels or post-execution terrain. Anchor/seed IDs are provenance and split controls, not desired model features. A single-Path evaluator scores execution conditional on one fixed Path and current observation; a complete navigation-policy evaluator would additionally score a specified sequence of future replans and observations.

## 5. Minimal controlled identifiability pilot — proposal only

1. **Freeze before outcomes:** choose the two already informative StateGroups (`first-differential`, `second-graded`) for a diagnostic, not a generalization claim. Use direct twice as a duplicate control plus −20° and +20° Paths. Two independent keyed-noise blocks per StateGroup give **4 paired units and 16 trials**. The duplicate direct branches share the exact anchor and injected noise. Freeze slots, order, SHA, runner, limits and labels before Path publication. This is the smallest screening pilot; positive results would still need independent terrain/anchor expansion before learning.
2. **Single-Path exposure:** activate one frozen Path once with the unchanged production-equivalent exact-stamp ROS follower and normal Actor `act_inference()`. No replacements, extensions or control interventions. Advance physics and `/clock` by 50 ms per control step; require one fresh exact-stamp TF/accepted command at each step, and record wall callback cadence. **On local-goal arrival, continue exactly 2 s (40 control steps) to verify stop hold, then end that trial. Only an unreached trial continues to 30 s (600 steps); if arrival occurs near 30 s, its stop check may end near 32 s.** The unreached cap is a right-censoring boundary, not a failure label. Any production-latest-TF equivalence claim requires a separate protocol check because the exact-stamp implementation is intentionally different.
3. **Measurement and duplicate gate:** direct duplicate pre-Path state, DEM, Actor input, noise, and Path SHA must meet the prior pre-Path contract (root XY ≤0.005 m, z ≤0.002 m, yaw ≤0.01 rad, joint position ≤0.005 rad, joint velocity ≤0.02 rad/s, root velocity ≤0.01 in frozen state units; DEM frame identity/shape/coordinates exact with the already specified numeric DEM RMS/mask IoU checks). Direct duplicate local-arrival/censoring and recovery categories must agree; if both arrive, first-arrival times must differ by ≤0.10 s. Proposed continuous floors are cross-track mean difference ≤0.02 m and 2 s common-goal progress spread <0.025 m. Report command/trajectory variation separately and stop if it approaches candidate variation. All published Paths, TF requests, accepted commands, 50 ms logical stamps, reward/contact and terminal records must be complete. No stale command may be silently reused after TF/bridge loss. Abort/record instability, resource excess, unexpected recovery before sufficient logical time, or branch interference; do not retry a Path-published trial.
4. **Execution-quality identifiability gate:** compare local arrival/censoring, time to arrival, tracking error, recovery and body load first. For continuous fields, require a reproducible candidate difference larger than **3× direct-duplicate spread** in both blocks of at least one StateGroup; a categorical difference requires duplicate categories to agree. Record the 0.05 m common-goal progress floor as a **separate** navigation-progress diagnostic, not the pass criterion for local execution. Compute offline geometry-only expectations from each Path's endpoint displacement, arc length and ideal same-speed arrival; compare ±20° paths, which have equal arc length and equal endpoint distance to the common goal. A difference explained only by those geometric quantities, or by early follower command geometry without a corresponding execution/terrain-response difference, is **not** evidence that embodiment-aware quality is identifiable. Evidence beyond that baseline requires repeatable differences in realized tracking, recovery or body load, interpreted together with pre-Path DEM corridor differences. With only two StateGroups, even a pass shows candidate-dependent execution in these cases, not terrain-wide embodiment-aware generalization. Report common-goal progress and any conflict with local arrival separately. If the distinction cannot be made, mark this gate `inconclusive` and do not train an Evaluator.

### Pre-pilot runtime gates (defined now; not executed)

1. **Actual host readiness:** immediately before any authorized runtime, on the same host and user environment used by the pilot, recheck `nvidia-smi` GPU/driver/memory, Docker NVIDIA device access, image/container identity, Isaac Lab/Onix source and checkpoint/follower hashes, free disk/RAM, and external router identity. The current host GPU and image checks pass statically; the stopped container cannot establish Isaac Lab launch/physics readiness.
2. **Isaac Lab startup gate:** after separate approval to run, launch a candidate-free diagnostic on that host and require successful SimulationApp/Isaac Lab import, first reset and physics stepping with finite Actor/DEM/contact. Record GPU peak and native exit. A failure stops before any Path candidate is published.
3. **30 s clock/TF/command gate:** before the 16 trial pilot, run a bounded 600-step, 20 Hz timing preflight using the actual ROS follower, bridge and simulator clock protocol but excluding candidate Outcomes. Assert 600 strictly increasing `/clock` stamps separated by 50 ms; at each control boundary the TF request/returned stamp, follower command stamp and bridge acceptance stamp equal the same logical stamp. Verify callback delivery, zero pre-Path adopted commands, no stale command reuse, and no missing/duplicate accepted command per step after a fixed diagnostic Path is activated. A failure, timeout, unexpected process residual or resource-cap breach stops the pilot. This preflight itself is a new runtime operation and **was not executed** here; its exact diagnostic Path and resource cap must be frozen before approval.

This pilot tests whether a *local Path* causes measurable execution differences. The two selected cases and four paired units cannot establish terrain-wide ranking accuracy, policy benefit, or calibrated success probabilities. No full collection or training follows automatically.
